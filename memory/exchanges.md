- [2026-09-14] Raw field names the normalizer will need per USDT-M message type (all pass through the collector untouched): **aggTrade** data object -- `a` (aggregate trade id, NOT a 1:1 execution id like spot's `t` -- multiple fills can share one `a`), `p`, `q`, `f`/`l` (first/last trade ids aggregated), `T` (trade time), `m` (buyer-is-maker). **depth diff** data object -- `U`, `u`, `pu` (previous update id -- futures-only continuity field, absent on spot; futures continuity is `current.pu == previous.u`, NOT `U == prev.u+1`), `b`/`a` (bid/ask deltas). **markPrice** data object -- `p` (mark price), `i` (index price), `r` (funding rate), `T` (next funding time); freezes outside trading hours for XAUUSDT/XAGUSDT specifically (see binance.md XAUUSDT/XAGUSDT caveat) -- adapter does not special-case this, normalizer must. **forceOrder** data object -- nested under `o`: `s` (symbol), `S` (side), `p`/`ap` (price/avg price), `q`/`z` (quantity/filled qty), `T` (order trade time); binance.md: this is a best-of-last-1000ms snapshot, not a full liquidation tape. (source: this session, Binance USDT-M futures WS message shapes per binance.md + standard fapi schema, src/exchanges/binance/usdtm.py docstrings)
- [2026-09-14] **Blocking gap for collector-agent, found while adding USDT-M perp**: `CollectorRunner._connect_and_stream` (src/collector/runner.py) only publishes messages classified as `kind == "depth_diff"` or `kind == "trade"` -- any other `stream_type()` return value (e.g. USDT-M's new "mark_price"/"liquidation" kinds) hits the `else` branch, which only does a `log.debug` and never calls `_sink.publish`. As written, markPrice and forceOrder messages from `BinanceUsdtmPerpAdapter` are silently dropped end-to-end and never reach Redis. `usdtm.py`'s `stream_type()` still returns the semantically correct kinds so only the runner's routing table needs to change (e.g. a generic passthrough stream keyed by kind), not the adapter -- not fixed here, src/collector/ is out of scope for exchange-adapter. (source: this session, src/collector/runner.py `_connect_and_stream`, read directly)
