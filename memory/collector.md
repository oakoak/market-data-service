- [2026-09-14] `ExchangeAdapter` protocol (src/collector/adapter.py) generalized for multi-connection exchanges: `ws_url() -> str` replaced by `ws_urls() -> dict[str, str]` (connection_name -> url); added `rest_pollers() -> dict[str, tuple[Callable[[], Awaitable[Any]], float]]` (poller_name -> (poll_fn, interval_s)), optional, return `{}` if none. `CollectorRunner.run()` now launches one independent asyncio task per `ws_urls()` entry (own reconnect/backoff, own disconnect/reconnect incident signal tagged with `raw.connection`=name) and one per `rest_pollers()` entry (interval loop, publishes to a new `{stream_prefix}:poll` Redis stream with `type`=poller name). Per-connection depth-diff buffer-until-snapshot dance now starts lazily on that connection's first `depth_diff` message rather than eagerly at connect -- so a connection that never carries depth diffs never calls `fetch_snapshot()`. `BinanceSpotAdapter.ws_urls()` returns a single-entry `{"combined": url}` dict; `rest_pollers()` returns `{}`. (source: this session, src/collector/adapter.py + runner.py + src/exchanges/binance/spot.py)
- [2026-09-14] Known gap for the next normalizer change: `NormalizerContext` in src/normalizer/consumer.py still tracks only one open `collector_disconnect` incident at a time (`self._open_disconnect`); with multiple named WS connections per adapter, concurrent disconnects on different connections will clobber each other. The collector-side disconnect/reconnect signal payload already carries `raw.connection` (the named connection) so normalizer-agent can key incidents per connection when it picks this up -- not fixed in this change (out of scope, src/normalizer/ not touched). (source: this session, src/collector/runner.py `_emit_signal`)

- [2026-09-14] Fixed: `CollectorRunner._connect_and_stream` (src/collector/runner.py) used to only publish messages classified as `depth_diff` or `trade` -- any other `stream_type()` result (e.g. USDT-M perp's `mark_price`, `liquidation`) hit an `else` branch that only logged a debug line and never called `_sink.publish()`, silently dropping that data end-to-end. Generalized: every classification is now published via one generic `_publish(kind, message, receive_ts)` + `_stream_for_kind(kind)` router. `depth_diff`/`trade` keep their existing stream names (`{stream_prefix}:depth`, `{stream_prefix}:trades`) unchanged; any other kind gets its own `{stream_prefix}:{kind}` stream (e.g. `{stream_prefix}:mark_price`, `{stream_prefix}:liquidation`); a falsy/"unknown" kind falls back to `{stream_prefix}:other`. The depth_diff buffer-until-snapshot-ready dance is unaffected -- still gated strictly on `kind == "depth_diff"`, so mark_price/liquidation arriving on the same "market" WS connection do not touch buffering state. normalizer-agent needs a new consumer per new stream to actually process mark_price/liquidation (not added here, src/normalizer/ untouched). (source: this session, src/collector/runner.py `_publish`/`_stream_for_kind`, reported by exchange-adapter subagent)

- [2026-09-14] Fixed: `Config.stream_prefix` (src/collector/config.py) was missing `segment` (`f"raw:{exchange}:{symbol.lower()}"`), which would collide Redis stream names across concurrent segments of the same exchange/symbol (e.g. binance spot BTCUSDT vs binance usdtm BTCUSDT both writing `raw:binance:btcusdt:trades`). Now `f"raw:{exchange}:{segment}:{symbol.lower()}"`. All collector stream names (`_trades_stream`, `_depth_stream`, `_poll_stream`, `_other_stream`, and the kind-routed `{stream_prefix}:{kind}` streams from runner.py) derive from this one property, so no other call site needed changes. Must match `normalizer/config.py`'s `stream_prefix` (normalizer-agent fixing that side to the same format). (source: this session, src/collector/config.py, reported by normalizer-agent)
